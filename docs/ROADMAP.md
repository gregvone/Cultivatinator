# Roadmap

1. **Foundation, Culture Library 2A and Provenance 2B — implemented.** SQLite/Alembic, Docker persistence, reference strains, acquisitions, individual cultures, permanent IDs, photographs, history, archive/restore, genetic origins, clones, isolates, spore establishments and shared/specific grow provenance.
2. **2C.1 — implemented.** Dashboard Quick Create, material-specific source selection, Create From This and context-preserving legacy redirects. See [2C.1](MILESTONE_2C1.md).
3. **2C.2 — merged.** Four Recipes categories (LC Media, Agar, Spawn Seed, Substrate); designated default LC media and inherited syringe media; direct cultivation without equipment, purchases, empty-container stock or ingredient accounting. Automatic physical labels are distinct from permanent biological IDs, with reusable container occupancy/history, explicit agar/spawn readiness and one-operation agar consumption. Acquisitions receives outside material; Culture Library owns Add Strain. Measured LC withdrawals and existing preparation/accounting records remain compatible. See [2C.2](MILESTONE_2C2.md) and [label/lifecycle rules](CONTAINER_LABELS.md).
4. **2C.3 — merged.** One Ready spawn source creates multiple permanently tracked FR containers atomically, with reusable F labels, immutable Substrate/environment snapshots and exactly-once spawn consumption. Dated Colonizing → Pinning → Fruiting → Harvest, multiple harvests per flush, Next Flush, optional wet/dry weights and subjective potency, exact harvest photos and revision history. Finish Grow/Failed explicitly release labels; harvests do not. One optional tent configuration and dated grow-specific changes require no daily logs, equipment counts or substrate inventory. Per-grow measured totals/timing are available. Legacy manual provenance remains readable without invented earlier events. See [2C.3](MILESTONE_2C3.md).
5. **2C.4 — merged.** Shared collapsible panels, consistent record headers and visible action controls, compact flush journals, mobile/keyboard accessibility and preserved form/photo retry state. See [2C.4](MILESTONE_2C4.md).
6. **2D.1 — merged.** Read-only Reports compares average fully measured wet yield per completed FR by strain, genetic culture line and original substrate recipe. Includes source/sample counts, incomplete coverage, saved recipe revisions, recorded-date timing, flush performance, terminal failure rates, separate active records and permanent-record drill-downs. No new cultivation inputs or daily logs. See [2D.1](MILESTONE_2D1.md).
7. **2D.2 — implemented, awaiting review and Debian acceptance.** Settings provides administrator unlock, manual server/download/both backups, a managed catalog and upload/stored browser restore. In-process weekly scheduling defaults to Sunday 03:00 America/New_York with 12 automatic archives; manual/recovery copies persist. A root-owned Unix-only host helper handles confirmed stop/restore/restart, writer fencing, retained safety/original data, health checks, rollback and interrupted recovery while keeping Docker access out of the app. Co-located Git/source/Compose/`.env`, backups, schedules and credentials are preserved. Existing ZIP/schema/CLI remain compatible; no migration or cloud service is added. See [2D.2](MILESTONE_2D2.md).
8. **Later — Experimental Genetics.** Preserve clones, isolates, spore-derived cultures, candidate crosses and confirmed crosses. Keep potential parents separate from confirmed genetic parents. Mixing strains is never evidence of a successful cross. No elaborate breeding module in 2C.2.

Existing permanent IDs, genetic genealogy, physical provenance, photographs, recipe snapshots, acquisitions, archive/history and LC volume accounting must remain intact. Archiving is a visibility action and never releases an occupied physical label. Optional sensors remain future work; remote storage and automatic cloud synchronization are outside 2D.2. No purchase, equipment inventory or preparation setup is required by the practical cultivation workflow.
